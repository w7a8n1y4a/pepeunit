# Рефактор фронтенда в клиент

Клиент — Flutter-приложение в этом репозитории. Ограничения UI лежат в коде и в `.cursor/rules/` (`client.mdc`, `hive-ui.mdc`, `hex-layout.mdc`, `hex-scale.mdc`). Здесь только то, что ещё предстоит сделать. Реализованное описано в коде и правилах.

## Library

Сейчас заглушка «Скоро». План: документация-дерево; миниигры (хотя бы микро-казино на фейк-койнах).

Формат — md (допустимы подстатьи):

- тултипы на сотах/параметрах
- дерево статей в Library
- подсказки по спец-иконкам (например `sight.svg`)
- у datapipe, появяляются кнопки с вводом шаблонов, для каждого типа политики (4 шт суммарно).  (отдельная дока уже есть в `docs/ru/user/datapipe/`).
- Поиск пути до функционала, т.е. вводим название, а получаем путь как до него добраться
- Режим дерева, чтобы видеть структуру сот ()
- Инструменты: генерация README.md по pepeunit.toml

## Обновления

- Бинарники и md-инструкция в ассетах релизов GitLab/GitHub
- Клиент сравнивает версию с релизами и предлагает обновление
- Web: owner — плашка обновления сервера; остальные — обновления клиента
- Текст инструкции — в Settings / About с бейджем на соте

## Вывод ошибок

- на основе error_codes ручки, к коду привязывается текст ошибки на нужном языке
