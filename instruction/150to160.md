1. Изучить текущий код и имеющиеся `AGENTS.md` во всех четырёх репозиториях. Ориентироваться на правила соответствующего `AGENTS.md` и существующий код.

3. Одно ревью охватывает один законченный результат и **не более 500 строк** суммарно по четырём репозиториям. Считать добавления плюс удаления от последнего принятого состояния. Замена одной строки расходует две строки лимита. В подсчёт входят все файлы, включая код, миграции, тестовые данные, конфигурацию и документацию.
4. Перед передачей на ревью снять `git diff --numstat <база>` в каждом затронутом репозитории и прибавить строки новых файлов вне индекса. Исправления до приёмки считать от той же базы. В отчёте указать фактические добавления, удаления и сумму, выполненные требования, изменения контрактов, миграции, проверки и действия для человека.
5. До начала замены включить в оценку удаляемый код и его фикстуры. Если сумма больше 500 строк, делить работу по потребителям или общим частям реализации. В каждом ревью должен работать весь затронутый путь. После передачи каждой части остановиться. Следующую начинать после приёмки человеком.
6. В ходе реализации не писать новые модульные и интеграционные тесты. После завершения всей реализации интеграционные тесты напишет владелец проекта. Локальные проверки проводить согласно `AGENTS.md` с учётом этих ограничений.
7. `git add`, коммиты, push и публикации выполняет только человек. Публикация пакетов в PyPI в объём работы не входит.

### 1. Формат схемы

Если в рабочем дереве подготовлено несколько частей, на ревью брать только файлы или фрагменты текущей части и её примеры из `tests/data/unit_manifest/`. Размер считать по её патчу. После приёмки 1.7.3 перейти к 2.1.

Манифест Unit — единый контракт, который определяет схемы `unit.yml` и `dictionary.yml` и правила их совместного применения. Оба файла объявляют одну и ту же строку `contract_version`. Допустимы формы `v<major>` и `v<major>.<minor>`, например `v1`, `v1.2` и `v3`. На этапе 1.2 Backend поддерживает контракт `v1`.

Репозиторий декодирует `unit.yml` один раз и проверяет `contract_version` до чтения словаря. Для поддерживаемой версии он открывает `app/schemas/unit_manifest/<contract_version>/dictionary.yml` и требует точного совпадения заголовков обоих файлов. Неизвестную версию отклоняет. Например, при `contract_version: v1.2` использовать словарь `v1` нельзя. Поддерживаемые версии перечислены в `ManifestContractVersion`, а имя файла задаёт `SchemaFileName.DICTIONARY`.

Имена IO уникальны во всём `unit.yml`, включая пересечение `input` и `output`. Имена IO из словаря зарезервированы вместе с направлением: объявление `state: {}` включает стандартный Output; любые свойства, включая тип и ограничения, либо неверное направление являются ошибкой. Схема раскрывается по имени из словаря контракта. Маркера `base` нет.

Определения IO хранятся в Git, без копий `base` и `io_schema` в `units_io`. Строка UnitIO соответствует ключу `topic_name` в `input` или `output` манифеста точного целевого коммита Unit. Существующий `Unit.target_commit` всегда содержит этот коммит, в том числе при автообновлении; флаги и ветка задают правила выбора следующей версии. Дополнительное поле коммита не требуется. `current_commit_version` остаётся версией, сообщённой устройством. Обновление `target_commit`, типа исполнения и набора IO выполняется одной транзакцией; при ошибке всё остаётся на прежней версии. Движение ветки само по себе не меняет действующую схему. Все потребители читают сохранённый коммит, повторно выбирают версию только при создании или обновлении Unit. Нужные Git-объекты сохраняются, опубликованный словарь контракта неизменяем.

#### Контракт максимального размера `.env` для ревью 3.4

Для валидной схемы расчёт возвращает HTTP 200. Если разрешённая строка `env.MESSAGE` не имеет конечной верхней границы, ответ имеет вид

```json
{"bounded": false, "max_bytes": null, "unbounded_fields": ["env.MESSAGE"]}
```

При конечной границе `bounded` равен `true`, `max_bytes` содержит целое число байт, а `unbounded_fields` пуст. Расчёт следует правилам сериализации `.env` и учитывает UTF-8, имена ключей, `=`, экранирование, переводы строк и служебные `PU_*`. Для вложенного поля возвращается путь. Ответ содержит только информацию о размере и имена полей.
