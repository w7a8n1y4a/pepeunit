### 1. Формат схемы

Если в рабочем дереве подготовлено несколько частей, на ревью брать только файлы или фрагменты текущей части и её примеры из `tests/data/unit_manifest/`. Размер считать по её патчу. После приёмки 1.7.3 перейти к 2.1.

Манифест Unit — единый контракт, который определяет схемы `unit.yml` и `dictionary.yml` и правила их совместного применения. Оба файла объявляют одну и ту же строку `contract_version`. Допустимы формы `v<major>` и `v<major>.<minor>`, например `v1`, `v1.2` и `v3`. На этапе 1.2 Backend поддерживает контракт `v1`.

Репозиторий декодирует `unit.yml` один раз и проверяет `contract_version` до чтения словаря. Для поддерживаемой версии он открывает `app/schemas/unit_manifest/<contract_version>/dictionary.yml` и требует точного совпадения заголовков обоих файлов. Неизвестную версию отклоняет. Например, при `contract_version: v1.2` использовать словарь `v1` нельзя. Поддерживаемые версии перечислены в `ManifestContractVersion`, а имя файла задаёт `SchemaFileName.DICTIONARY`.

Имена IO уникальны во всей раскрытой схеме, включая пересечение `input` и `output`. Символ `/` в имени запрещён. Backend автоматически добавляет все служебные Input и Output из словаря выбранного контракта. Автор объявляет в `unit.yml` свои IO. Прежнее пустое объявление служебного IO в его направлении допустимо для старых коммитов. Любые свойства в таком объявлении и использование имени в другом направлении дают ошибку.

Пользовательские определения IO хранятся в Git. Строка UnitIO соответствует ключу `topic_name` в `input` или `output` схемы, собранной из `unit.yml` выбранного коммита и словаря его контракта. `Unit.target_commit` хранит ручной выбор и допускает NULL. `resolve_auto_commit_and_tag` вычисляет `(resolved_commit, resolved_tag)` из локального Git по ветке и флагам. `get_selected_commit_and_tag` возвращает `(selected_commit, selected_tag)` для обоих режимов. Это проверенный ручной выбор или коммит, вычисленный для автообновления, вместе с его тегом. В `current_commit_version` хранится SHA, сообщённый устройством (`device_commit`). Создание и обновление проверяют манифест по `selected_commit` и одной транзакцией сохраняют настройки Unit, тип исполнения и набор IO. Существующие Unit получают недостающие служебные IO при ближайшей штатной синхронизации. При ошибке проверки или записи прежнее состояние сохраняется целиком.

Ошибка схемы указывает путь до отсутствующего или недопустимого ограничения. `default` и `example` задают значения внутри границ.

#### Контракт максимального размера `.env` для ревью 3.4

`GET /units/env/{uuid}/max_size` доступен владельцу Unit и самому устройству. Backend берёт `unit.yml` из `selected_commit` и словарь его контракта. Изменяемые настройки, включая `PU_*`, считаются на пределах схемы, а заданные сервером `PU_*` — по их текущим сериализованным значениям. Допустимые необязательные поля входят в максимум. Если обязательное поле невозможно заполнить по схеме, backend возвращает ошибку манифеста с именем поля.

HTTP 200 содержит `max_chars`. В число входят имена переменных, `=`, кавычки, экранирование и LF. Файл передаётся в UTF-8, где одна кодовая точка занимает от одного до четырёх байт.

```json
{"max_chars": 1268}
```
