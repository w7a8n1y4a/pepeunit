# Добавление Instance

:::info Где найти?
Иконка `Instances` в верхней панели, затем кнопка `Add Instance`. Добавлять, подтверждать, блокировать и удалять инстансы может только [Администратор](/development-pepeunit/mechanics/roles#admin)
:::

## Ссылка About

Чтобы добавить внешний инстанс, нужна ссылка на его публичное состояние `/instances/current`. На внешнем инстансе её может скопировать любой авторизованный [Пользователь](/development-pepeunit/mechanics/roles#user) в разделе `About`.

1. Войдите в нужный инстанс
1. Нажмите своё имя в правом верхнем углу
1. Нажмите `About`
1. В блоке `Current Instance` скопируйте ссылку кнопкой рядом с ней

Формат ссылки:

```
https://domain.com/pepeunit/api/v1/instances/current
```

:::warning
Ссылка должна заканчиваться на `/instances/current`. Схема только `http` или `https`. Нельзя добавлять `query`, `fragment` и логин с паролем в `URL`
:::

## Как добавить Instance

1. Откройте модальное окно `Instances`
1. Нажмите `Add Instance`
1. Вставьте ссылку `/current` в поле `Paste /current links`
1. Нажмите `Add`

После успешного добавления инстанс сразу получает статус `Trust` и появляется в списке.

:::info
Инстансы могут находиться и сами. Раз в час текущий инстанс опрашивает всех соседей со статусом `Trust`, забирает у них списки известных URL и публичных [RepositoryRegistry](/definitions#repositoryregistry). Новые URL создаются со статусом `Pending`. Статус доверия им выставляет только [Администратор](/development-pepeunit/mechanics/roles#admin): без `Trust` найденный инстанс не опрашивается
:::

## Подтверждение, блокировка и удаление

Действия доступны в строке списка `Instances` и зависят от текущего статуса.

Статус | Доступные кнопки
-- | --
`Pending` | `Trust`, `Block`, `Delete`
`Trust` | `Block`, `Scan`, `Delete`
`Blocking` | `Trust`, `Delete`

1. `Trust` - начать опрос инстанса и принимать от него данные
1. `Block` - прекратить опрос. Ответам такого инстанса текущий инстанс не доверяет
1. `Scan` - принудительно опросить один доверенный инстанс. Создаётся [Operation Task](/definitions#operation-task) типа `Scan Instance`
1. `Delete` - удалить запись

:::warning
Статус `Pending` [Администратор](/development-pepeunit/mechanics/roles#admin) выставить не может. Это карантин только для автоматически найденных инстансов. Такие записи не опрашиваются и не удаляются по сроку давности
:::

## Принудительное сканирование всех инстансов

В списке `Instances` кнопка `Scan All` запускает опрос всех записей со статусом `Trust`. Задача растягивается примерно на `10` минут, чтобы не ударить по сети сразу. Повторный запуск той же команды недоступен в течение `10` минут.

Создаётся [Operation Task](/definitions#operation-task) типа `Scan All Instances`. Результат выглядит как `Scanned N, failed M`.

## Автоматический опрос и хранение

Если флаг `PU_FF_FEDERATION_ENABLE` включён, [Backend](/deployment/dependencies/backend) каждый час опрашивает доверенные инстансы. Перед опросом каждому инстансу назначается случайная задержка `1-3600 c`

Инстанс со статусом `Trust` удаляется, если успешный опрос не удавался дольше `PU_INSTANCE_RETENTION_DAYS`. Перед удалением выполняется обязательный повторный опрос. Записи `Pending` автоматически не удаляются.

Связанные переменные [Backend](/deployment/env-variables/backend):

Переменная | Зачем нужна
-- | --
`PU_FF_FEDERATION_ENABLE` | Включает опрос внешних инстансов и кнопки сканирования
`PU_INSTANCE_RETENTION_DAYS` | Сколько дней без успешного опроса хранить доверенный инстанс, `1`–`120`
`PU_INSTANCE_MAX_STATE_SIZE` | Максимальный размер ответа внешнего инстанса в байтах, `4096`–`65536`
`PU_ADMIN_EMAIL` | Публичный email, который попадёт в контакты текущего инстанса
`PU_ADMIN_TG` | Публичный контакт [Telegram](/definitions#telegram) в карточке текущего инстанса
`PU_HTTP_TIMEOUT` | Таймаут исходящих запросов к внешним инстансам
`PU_HTTP_CONNECT_TIMEOUT` | Таймаут установки соединения при опросе
