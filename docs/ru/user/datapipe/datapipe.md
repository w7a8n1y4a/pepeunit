# DataPipe

[DataPipe](/deployment/dependencies/datapipe) - конвейер, который принимает значения топика `UnitIO`, фильтрует, преобразует и сохраняет их по выбранной политике. Свой конвейер у каждого `UnitIO`, а описывается он YAML конфигом.

Путь к нему: `Аппараты` → `Unit` → `Входы и выходы` → нужный `UnitIO` → `DataPipe`. Сота есть у создателя `UnitIO`, если DataPipe включён на инстансе (`pu_ff_datapipe_enable`) и топик оканчивается на `/pepeunit`.

## Включение

1. Включите соту `DataPipe`: пока она `выкл`, остальные соты не работают
1. `Редактор`: пустой конфиг начнётся с шаблона `LastValue`. Задайте нужный и нажмите `Сохранить`
1. `Загрузить данные`, `Выгрузить данные` и `Удалить все данные` работают с накопленными записями, см. [Импорт данных](/user/datapipe/import)

Если включена настройка инстанса `pu_datapipe_default_last_value_enable`, такие `UnitIO` создаются сразу с политикой `LastValue`.

## Редактор

Кнопка | Что делает
-- | --
`Сохранить` | Проверяет и сохраняет конфиг. Недоступна, пока в тексте есть ошибки
`Проверить` | Проверяет синтаксис и правила, ничего не сохраняя
`Загрузить` | Загружает конфиг из файла `YML` в редактор
`Выгрузить` | Сохраняет текст редактора в файл `YML`
`LastValue`, `NRecords`, `TimeWindow`, `Aggregation`, `Alerts` | Копируют готовый [пример](/user/datapipe/example) в буфер обмена, текст редактора не меняется

Текст проверяется при вводе: синтаксис `YML` сразу, правила конвейера сервером. Ошибки выводятся под редактором.

## Значение параметров

Обязательные этапы конвейера: `active_period`, `filters`, `processing_policy`. Необязательные: `transformations` и `alerts`

## active_period

Ограничивает время сбора данных: за период, с даты, до даты или постоянно.

Название параметра | Возможные значения | Обязательный? | Комментарий
-- | -- | -- | --
`type` | `DateRange`, `FromDate`, `ToDate`, `Permanent` | Да | Выбор ограничения времени
`start` | Дата в формате `2023-11-15T12:43:56Z` | Обязателен для типов: `DateRange` и `FromDate` | Время начала периода `DateRange` или время начала работы `FromDate`. Для `DateRange` меньше `end`
`end` | Дата в формате `2023-11-15T12:43:56Z` | Обязателен для типов: `DateRange` и `ToDate` | Время конца периода `DateRange` или время конца работы `ToDate`

## filters

Название параметра | Возможные значения | Обязательный? | Комментарий
-- | -- | -- | --
`type_input_value` | `Text` или `Number` | Да | Тип обрабатываемых данных. `Number` это `float64` из Golang
`type_value_filtering` | `WhiteList` и `BlackList` | Нет | Тип фильтрации значений
`filtering_values` | Список только числовых или только текстовых значений | Обязателен в случае, если есть `type_value_filtering` | Проверка завязана на тип из `type_input_value`
`type_value_threshold` | `Min`, `Max` или `Range` | Нет | Тип фильтрации диапазонов числовых значений
`threshold_min` | Целое | Обязателен, если есть `type_value_threshold` с типами `Min` и `Range` | Работает только с `type_input_value` = `Number`. Для `Range` меньше `threshold_max`
`threshold_max` | Целое | Обязателен, если есть `type_value_threshold` с типами `Max` и `Range` | Работает только с `type_input_value` = `Number`
`max_rate` | `0 <= max_rate <= 86400` только целые | Да | Через сколько секунд будет обработано следующее сообщение. `0` без ограничения
`last_unique_check` | `true`, `false` | Да | Если `true`, то пропустит только если новое значение отличается от предыдущего. По умолчанию `false`
`max_size` | `0 <= max_size <= pu_mqtt_max_payload_size * 1024` | Да | Максимальная длина сообщения в символах, более длинное пропускается. `0` без ограничения. `pu_mqtt_max_payload_size` - [настройка инстанса](/deployment/instance-settings#mqtt)

## transformations

Параметры зависят от `type_input_value` из `filters`.

Для `type_input_value` = `Number`:
Название параметра | Возможные значения | Обязательный? | Комментарий
-- | -- | -- | --
`multiplication_ratio` | `float64` из Golang | Нет | На это число можно умножить заданное значение - линейное преобразование
`round_decimal_point` | `0 <= round_decimal_point <= 7` | Нет | Сколько чисел после запятой останется?

Для `type_input_value` = `Text`:
Название параметра | Возможные значения | Обязательный? | Комментарий
-- | -- | -- | --
`slice_start` | Целое число | Нет | Работает как первый элемент среза в `python3` - `any_list[slice_start:]`
`slice_end` | Целое число | Нет | Работает как второй элемент среза в `python3` - `any_list[:slice_end]`

## processing_policy

Название параметра | Возможные значения | Обязательный? | Комментарий
-- | -- | -- | --
`policy_type` | `LastValue`, `NRecords`, `TimeWindow`, `Aggregation` | Да | Одна из `4` политик обработки
`n_records_count` | Число хранимых записей `0 < n_records_count =< 1024` | Обязателен только для `policy_type` = `NRecords` | Определяет, сколько записей будет храниться
`time_window_size` | Одно из значений: `[60, 300, 600, 900, 1200, 1800, 3600, 7200, 10800, 14400, 21600, 28800, 43200, 86400]` | Обязателен для `policy_type` = `TimeWindow` или `Aggregation` | Размер окна в секундах, оно должно нацело делить `86400`
`aggregation_functions` | `Avg`, `Min`, `Max`, `Sum` | Обязателен для `policy_type` = `Aggregation` | Функция, на основе которой будет рассчитано итоговое значение, на основе `time_window_size`

## alerts

Проверяет значение, которое уже прошло `filters` и `transformations`, и пишет уведомление создателю `UnitIO`. Условие совпадает с этапом `filters`: уведомление уходит на значение, которое такой же фильтр пропустил бы.

`WhiteList` срабатывает, когда значение есть в `filtering_values`. `BlackList` срабатывает, когда значения в списке нет. `Min` срабатывает при значении больше либо равном `threshold_min`, `Max` при значении меньше либо равном `threshold_max`, `Range` когда значение внутри обеих границ. Если заданы и список, и порог, значение должно пройти оба правила. Если не заданы ни `type_value_filtering`, ни `type_value_threshold`, уведомление создаётся на любое значение: достаточно `is_enabled`.

`max_rate` и `last_unique_check` из `filters` решают, какие значения вообще дойдут до этой проверки. Первое уведомление уходит после `consecutive_count` совпадений подряд. Пока значение остаётся совпадением, следующее уведомление того же `UnitIO` приходит не чаще чем раз в `max_frequency` секунд. Значение, которое не совпало с правилом, сбрасывает счётчик `consecutive_count`.

Этап работает при включённой настройке инстанса `pu_ff_notification_enable`. Если выключить `DataPipe` в [настройках уведомлений](/user/alerts#настройки), правило остаётся в конвейере, но уведомления перестают приходить.

Название параметра | Возможные значения | Обязательный? | Комментарий
-- | -- | -- | --
`is_enabled` | `true`, `false` | Нет, по умолчанию `true` | `false` выключает проверку
`type_value_filtering` | `WhiteList`, `BlackList` | Нет | Тип списка
`filtering_values` | Список чисел или строк | Обязателен, если задан `type_value_filtering` | Тип значений берётся из `filters.type_input_value`
`type_value_threshold` | `Min`, `Max`, `Range` | Нет | Только при `filters.type_input_value` = `Number`
`threshold_min` | Целое | Обязателен для `Min` и `Range` | Для `Range` меньше `threshold_max`
`threshold_max` | Целое | Обязателен для `Max` и `Range` | Для `Range` больше `threshold_min`
`consecutive_count` | Целое `1`–`1024`, по умолчанию `1` | Нет | Сколько совпадений подряд нужно до первого уведомления
`max_frequency` | Целое `10`–`86400`, по умолчанию `10` | Нет | Минимум секунд между двумя уведомлениями одного `UnitIO`
