# Уровни видимости - Public, Internal и Private

От уровня видимости сущности зависит, кто может найти её, получить о ней информацию и работать с ней как с чужой.

Уровень видимости есть только у [Unit и UnitIO](/development-pepeunit/mechanics/entities#основные-сущности). `UnitGroup`, `Dashboard`, `Notification` и настройки видит только создатель.

Уровень видимости | Кто видит
-- | --
`Public` | Все, в том числе [Bot](/development-pepeunit/mechanics/roles#bot), который не вошёл в аккаунт
`Internal` | Любой вошедший [User](/development-pepeunit/mechanics/roles#user) и любой `Unit` этого инстанса
`Private` | Создатель и агенты, которым создатель выдал [доступ](/development-pepeunit/mechanics/permission), то есть `User` и `Unit`. Работает в пределах инстанса

Роль не даёт обхода видимости: `Admin` и `Owner` видят чужой `Private` только с выданным доступом, как все. Исключение одно: внутренние вызовы `Backend`. Как проверяется доступ в запросах и списках, см. [Проверку доступа при запросах](/development-pepeunit/mechanics/permission#проверка-доступа-при-запросах).

У `Repo` уровней нет: публичный `Repo` видят все, приватный видят в списке все вошедшие `User`, а `Bot` не видит. Создатель не выдаёт доступ к приватному `Repo`: синхронизировать его и создавать из него `Unit` может только тот, кто указал свои Креды доступа к платформе и чьи Креды имеют статус `Valid`, см. [Repo](/development-pepeunit/mechanics/entities#repo).

## Связь Unit и UnitIO

`UnitIO` не может быть видимее своего `Unit`: если `Unit` стал строже, его `UnitIO` строже автоматически.

Уровень `Unit` | Какими могут быть `UnitIO`
-- | --
`Public` | Любыми: `Public`, `Internal` или `Private`
`Internal` | `Internal` или `Private`
`Private` | Только `Private`

Например, `Unit` стал `Private`: все его `UnitIO` с уровнем `Public` или `Internal` тоже стали `Private`. Если потом сделать `Unit` снова `Public`, они сами обратно не смягчатся: их уровень придётся вернуть вручную в `Настройки` каждого `UnitIO`.

Меняется видимость `Unit` в клиенте: `Аппараты` → `Unit` → `Настройки` → `Видимость`. Для `UnitIO`: `Unit` → `UnitIO` → `Настройки` → `Видимость`.

## Возможности создателя сущностей

Создатель имеет полный доступ по управлению своими сущностями.

### Repo

- Изменение своих Кредов доступа
- Синхронизация Git репозитория внутри Pepeunit
- Создание `Unit` на основе `Repo`
- Удаление `Repo`, если у него нет `Unit`

### Unit

- Просмотр версии, состояния и логов `Unit`
- Установка и сброс `env.json`
- Скачивание прошивки и [скомпилированных](/development-pepeunit/mechanics/update-system) пакетов
- Команды по MQTT: `Update`, `SchemaUpdate`, `EnvUpdate`, `LogSync` и `Reset`
- Настройки `Unit`: видимость, правила и версия обновления, иконка
- Выдача [доступов](/development-pepeunit/mechanics/permission)
- Удаление `Unit`

### UnitIO

- Просмотр состояния
- Установка значения в `Input` с отправкой через MQTT
- Создание и удаление `Link`
- Настройки `UnitIO`: видимость, `is_rewritable_input`, `max_connections`
- Выдача доступов
- Все аспекты управления [DataPipe](/deployment/dependencies/datapipe)

## Возможности агентов для видимых сущностей

Для чужих сущностей, которые агент увидел благодаря видимости или выданному доступу, возможности ограничены.

### Repo

- Просмотр информации о `Repo` и его размера
- Синхронизация и создание `Unit`. Для публичного `Repo` доступны всем `User`, для приватного только при Кредах со статусом `Valid`

### Unit

- Просмотр информации о текущей версии и состоянии `Unit`

### UnitIO

- Просмотр состояния
- Установка значений в `Input` с отправкой через MQTT. `Unit` вместо `User` может писать только в `Input` с включённым `is_rewritable_input`
- Создание `Link` между двумя видимыми `UnitIO`: выходом одного `Unit` и входом другого. Действует ограничение `max_connections` с обеих сторон, а оба `Unit` получают [Permission](/development-pepeunit/mechanics/permission#permission-от-link) на `UnitIO` друг друга

:::warning
Чужие `env.json`, логи, команды MQTT, прошивку и хранилище состояния `Unit` получить нельзя, даже если `Unit` `Public`. Добавить чужой `UnitIO` в `Dashboard` тоже нельзя: это может только создатель.
:::
