# Система сравнения инстансов

Задача системы - дать пользователям место на каждом инстансе, где они могут понять состояние сети Pepeunit

## Единый сервис парсер

1. Сервис опражшивает все инстансы которые он знает о их состоянии
1. Новые инстансы добавляются вручную админом
1. Сервис обходит все доступные инстансы за 1 час, равномерно распределяя запросы, т.е. не должно быть такого что все инстансы на планете за 1 секунду опросили все другие инстансы
    - опрашиваются ручка инкремента и domain.com/pepeunit
    - ручка общего списка доменов опрашивается 1 раз в неделю для каждого инстанса о котором знает текущий инстанс. Это нужно чтобы не нагружать другие инстанса, просто 1 раз в неделю каждый инстанс с каждым будет синхронить список
1. Записываем пинг запросов до инстансов, ip и понятное дело данные из ручки других инстансов domain.com/pepeunit ну и время последнего запроса

### Контракт
1. Ручка domain.com/pepeunit: Отдача состояния системы с настройками, ручку нужно сделать кешированной и обновлением 1 раз в час, т.к. её будут часто дёргать
1. Отдельная публичная ручка gql и rest отдающая список доменов, которые есть у инстанса. Пагинационный лимит на отдачу из этой ручки, чтобы небыло огромных пейлоадов, на этой ручке должны быть строгие лимиты
1. Отдельная публичная ручка gql и rest аналогичная предидущей, но она отдаёт только инкремент новых инстансов за последние 2 часа. На этой ручке должен быть кеш, обновляемый каждый час
1. Отдельная публичная ручка gql и rest которая будет давать 

Данные domain.com/pepeunit:
1. Базовые фича флаги инстанса
1. Базовые настройки инстанса
1. Когда в последний раз прошли интеграционники и результат (запуск админом)
1. Статистики инстанса
1. Контакты владельца инстанса
1. Убрать автора, стало избыточной информацией

Данные инкрементной ручки и общей:
1. все данные из таблицы реализации

## Добавление системы задач, для сложных кнопок которым нужно иметь статус

Создаём таблицу в бд для ручных задач. Сейчас нет возможности отследить статус выполнения некоторых важных кнопок:
1. Интеграционные тесты, можно будет запускать по кнопке с фронтенда админу. Это гарантия админу что pepeunit работает как надо.
1. Кнопка принудительного сканирования внешних инстансов, проходит по всем доменам отдельно и уточняет информацию
1. Кнопка принудительного сканирования конкретного инстанса
1. Кнопка узнающая у других инстансов, о их списке доменов, позволяет синхронизировать списки доменов у разных инстансов
1. Обновление всех registry массово
1. Обновление одиночных registry

## Реализация

Нужна таблица instances для хранения всех доступных инстансов:
- Домен инстанса
- статус доверия (по умолчанию всем даётся trust, админ может сменить руками в NoTrust)
- ip адрес инстансов
- ping
- Время сбора информации
- Накопительный каунтер, числа положительных сборов данных
- Статус последнего сбора информации
- Ошибка сбора если есть
- хранение json ответов целиком, работать будем по версии схем, чтобы добиться универсальности между разными инстансами. Каждая последующая версия, будет знать о нюансах предыдущих
