# MessageProcessor

DataPipe выносится в отдельный стейдж и в итоге получается MessageProcessor

## Этапы Message Proccessor

0. Все подписки сводятся к `domain.com/+` благодаря типизации и новым подходам
1. Счётчик
2. Валидация согласно схемы и счётчику
3. Преобразование размерностей величин
3. Пересылка в другие топики UnitIO
4. запись в исходном виде в DataPipe

## Ресурсы Инстанса во времени

1. Logporter позволяет получить рантайм cpu, ram и сеть
1. Prometheus позволит из Logporter получить уже окна - `[месяц, неделя, день, час]`
1. Занимаемые ресурсы постоянной памяти можно взять из postgres и clickhouse напрямую
1. Для того чтобы узнать сколько памяти всего осталось у хост системы нужен какой-то экспортер
1. Максимальное значение внешней сети нужно вводить в настройки инстанса, по умолчанию 100 МБ/c

- из этого собирается базовое общее понимание
- инстанс сможет прогнозировать динамику сколько ему ещё стабильно работать

## Ресурсы Unit во времени

1. Считаются все MPS входящие и исходящие на каждый UnitIO (на Unit просто через join c суммированием)
1. Среднее число сообщений от/на доманшний инстанс `[месяц, неделя, день, час]`
1. Среднее число сообщений от/на внешние инстансы `[месяц, неделя, день, час]`
1. Динамика размера памяти на основе строк `DataPipe` `[месяц, неделя, день, час]`
1. Выдаёт отказ в обслуживании при превышении лимитов

- из этого мы поймём процентное соотношение кто как потребляет какие ресурсы

## Перенос подписки из backend в MessageProcessor

- Backend больше никуда не подписывается по mqtt
- Backend больше не тригерит сам обновление схемы у Unit
- Backend оставляет себе только настройку EMQX и выдачу доступов
- Можно будет на Backend провести рефактор mqtt соединений
