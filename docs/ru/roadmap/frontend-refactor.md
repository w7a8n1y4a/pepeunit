# Рефатор фронтенда в клиент

## Изменения бекенда

1. Полное удаление GQL
1. В GET /instances/current диапазон допустимых версий клиента
1. Авторизация по подписям от приватников
1. Во все внешние схемы надо прописать utc 0
1. Добавление полей под кастомизацию глобального пользователя
    - ru/en
    - картинка png до 128КБ
    - регион utc +X
1. У инстансов должны появиться картинки
    - картинка png до 128КБ
    - исходник хранится у каждого инстанса в отдельном volume
    - в instances таблице появляется новое поле под эту картинку
    - у инстансов появляется отдельная ручка для отдачи этой картинки
    - сохранение этой картинки идёт 
1. Из-за глобальности аккаунтов, потребуется улучшить производительность и сделать улучшенное дросселирование/лимитирование по созданию аккаунтов и их апдейту.
    - апдейт не чаще чем 1 раз в час
    - нужно установить общий лимит на число пользователей, чтобы инстанс не упал при массовых ddos
1. Добавить функционал групп
    - 1 группа может содержать N Unit
    - 1 Unit может быть в N групп
    - Имя, не уникальное
    - Картинка png до 128КБ
    - У инстанса должен быть общий лимит, на число групп на 1 человека, по умолчанию 16
    - Основная цель
        - объединение для визуала, технической задачи у него не будет
    - Важно чтобы размещение в интерфейсе элементов груп, хранилось на стороне клиента, а не бека
1. Переименование Repo в UnitTemplate или аналог
1. Появляется новая роль Owner
    - старое присвоение первому пользователю Admin убирается
    - нужно придумать механизм присвоения owner, через ключи и env бекенда
    - часть функционала будет доступна только owner

### Вход в федерацию через глобальный аккаунт

На десктопе рождается постоянный ключ. В клиент, который ходит на инстансы, попадает только одноразовый промежуточный.

| # | Этап | Что происходит | Ключи |
|---|---|---|---|
| 1 | Регистрация | Десктоп генерирует постоянную пару и показывает seed-фразу. Сеть не нужна. | Постоянная пара пользователя. Приватный шифруется PIN и остаётся на десктопе. Публичный — имя аккаунта. |
| 2 | Опрос федерации | Десктоп читает карточки `/instances/current` и списки соседей. | Публичные ключи инстансов. Ключ, отданный нодой по своему URL, сверяется с копией у соседей. |
| 3 | Выбор нод | Пользователь отмечает, куда входить. | Уже сверенные публичные ключи выбранных инстансов. |
| 4 | Промежуточный ключ | Десктоп создаёт новую пару и подписывает допуск: постоянный публичный ключ, промежуточный публичный ключ, один вход на каждый выбранный инстанс, короткий срок. Файл с приватным промежуточным ключом и допуском отдаётся клиенту. | Допуск подписывает постоянный приватный ключ, он остаётся на десктопе. В файле лежит приватный промежуточный ключ. |
| 5 | Challenge | Клиент запрашивает у инстанса домен, одноразовый nonce и срок 1–2 минуты. | Публичный ключ инстанса подтверждает, что запрос ушёл на выбранную ноду. |
| 6 | Подпись | Клиент подписывает challenge и прикладывает допуск. | Приватный промежуточный ключ. Постоянный приватный ключ в этом шаге не участвует. |
| 7 | Проверка | Инстанс принимает ответ, если challenge свежий, домен его, подпись сходится с промежуточным публичным ключом, допуск подписан постоянным публичным ключом, срок жив, и этот допуск на этой ноде ещё не использован. После успеха нода помечает допуск использованным. | Публичный промежуточный ключ и постоянный публичный ключ. Повторный вход этим файлом на эту ноду уже не проходит. |
| 8 | Локальный пользователь | Инстанс находит или создаёт пользователя по постоянному публичному ключу. На пустой ноде он админ, на живой — обычный пользователь. | В базу пишется постоянный публичный ключ. Промежуточный ключ личностью не становится. |
| 9 | JWT | Инстанс выписывает токен со uuid локального пользователя на срок `pu_auth_token_expiration`, по умолчанию 31 день. | Токен подписывает секрет инстанса `pu_secret_key`. |


- Пункты 5–9 повторяются на каждом выбранном инстансе
- Подпись в пункте 6 каждый раз новая, файл один и тот же. На каждой ноде он сгорает отдельно.

## Требования к клиентским приложениям

1. Мультиязычность из настроек пользователя ru/en
1. Время в зависимости от utc региона из настроек
1. Документация интегрируется в клиент
    - Часть как подсказки при наведении на соты/параметры
    - Часть как отдельное дерево сот в глубину со статьями
    - Часть будет документации показывается при наведении на спец иконки (прицел например)
    - Формат документации md, возможно разделение на подстатьи
1. Система апдейтов
    - В ассетах релизов gitlab и github будут бинарники
    - Клиент должен сравнивать свою текущую версию с релизами
    - Клиент должен предлагать обновление 
    - Для веб развёртывания будет уведомение админам об новых апдейтах
    - Ассеты должны включать md инструкцию по обновлению, прямые шаги, которые нужно выполнить для обновления на разных платформах
1. Стейт менеджмент
    - Хранение данных глобального аккаунта
    - В зависимости от hard платформы json, браузерное хранилище и тд

## Интерфейсы

Все экраны состоят из сот: правильных гексогонов (шестигранников) - ориентированных вертикально. Вверху и внизу располагается угол, по бокам стороны.

### Фон

- Монотонная база
- Мозайка из svg c разными темами
    - Pepe
    - Исторические штуки
    - Прям египетские иероглифы
    - Славянские штуки
    - Нордические штуки
- Текст разными шрифтами опенсорсными
- Определённый участок фона должен расказывать историю svg как иероглифами
- Времена года должны отличаться
- Под праздники надо менять фон

### Позиционирование интерфейсов

- Всегда по центру
- Универсальное правило: интерфейс должен занимать максимум экрана, при этом сохраняя приятный для пользователя облик

1. Расположение по центру задаётся исходя из общего центра интерфейса
    - Если рендерится меню из сот и их 7, т.е. буквально 1 в центре и 6 по периметру, то центр интерфейса будет по центру центральной соты
    - Если рендерится меню из сот и их 10, т.е. первый ряд 3, второй ряд 4 и третий ряд 3, то центр интерфейса будет в центре второго ряда между 2 и 3 сотой.
    - Если соты имеют произвольное позиционирование, то они должны влезть в экран, а общий центр интерфейса должен быть вычислен геометрически
    - Если рендерится интерфейс отображения данных, то его центр берётся по основному гексагону рендера. Все остальные гексагоны находятся в области видимости, но не влияют на расположение
    - Если рендерится интерфейс формы, для вбивания данных, то он всегда в центре экрана, если он не влезает по вертикали, то появляется прокрутка
1. Пользователь может изменять масштаб
    - масштаб увеличивается ступенчато, и всегдя связан с добавлением элементов в рендер
    - если дополнительных элементов которые могут быть отрендерены из-за масштаба нет, то масштабирование останавливается
    - при увеличении масштаба могут добавляются новые соты или слои сот или дополнительные кнопки в виде сот
    - в интерфейсах масштаб статичен, и его нельзя изменить
1. Отсутпы зависят от соотношения сторон
    - в браузере на весь экран с соотношение сторон 16:9
        - размер интерфейса будет задаваться отступами сверху и снизу
        - боковые отступы должны будут под них подстроиться
    - на телефоне 9:19 
        - размер интерфейса будет задаваться отступами по бокам
        - отступы сверху и снизу будт подстраиваться
    - отступы в первую очередь подчиняются универсальному правилу

## Соты

Поле — это один инстанс. Вложенность видна всегда: реестр — земля, Repo — участок, Unit — сота. Ребро появляется, только когда сота открыта, и идёт от гнезда к гнезду.

| Сущность | Где она на поле |
|---|---|
| Instance | Другое поле. Переключатель уносит камеру туда |
| RepositoryRegistry | Земля: адрес, платформа, синхронизация |
| Repo | Участок внутри земли |
| Unit | Сота |
| UnitNode | Гнездо внутри открытой соты |
| UnitNodeEdge | Провод между гнёздами открытой соты |
| DataPipe | Метка и исходник гнезда |
| Visibility | Черта самой соты или гнезда |
| User | Тот, кто смотрит. Свои соты теплее |
| Permission | Список «кому открыто» у открытой соты, Repo или гнезда. Агент — человек или Unit |
| Dashboard и панель | Слой стекла поверх поля. Линза сидит на гнезде и снимается вместе со слоем |
| Уведомление | Лента у края. Нажатие переносит камеру к соте |
