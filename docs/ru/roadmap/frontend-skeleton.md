# Каркас клиента

Первый запуск клиента. Визуальные правила остаются в [преобразовании фронтенда](/roadmap/frontend-refactor). Имена сущностей и ручки берутся из OpenAPI бекенда `1.5.0`. Текущие статьи `docs/ru` и `docs/en` в каркас не входят.

Код живёт в каталоге `client/` этого репозитория. Меню, аккаунт, инстансы и запросы к бекенду — один Dart-код в `client/lib`, он собирается на web, linux, macos, windows, android и ios. Каталоги `android`, `ios`, `linux`, `macos`, `windows` и `web` — оболочки запуска, которые создаёт Flutter. От платформы зависит только место ключа: защищённое хранилище системы или, на вебе, хранилище браузера. Этот выбор спрятан за одним хранилищем аккаунта.

Ежедневная разработка идёт в браузере: `flutter run -d chrome` из `client/`. Страница остаётся открытой, `r` в терминале подхватывает правки. На этой машине бинарник Chrome называется `google-chrome-stable`, поэтому перед запуском нужен `export CHROME_EXECUTABLE=/usr/bin/google-chrome-stable`.

Клиент принимает бекенд `>= 1.5.0` и `< 1.6.0`. Версия читается из `GET /pepeunit/api/v1/instances/current`.

## Что умеет первый запуск

1. Меню. Семь сот главного меню. Вход в раздел кладёт кадр в стек, назад снимает кадр. На вебе стек повторяется адресом: `/` и `/{section}`. Активный инстанс в путь не входит.
2. Глобальный аккаунт создаётся на клиенте. Локально хранятся пара ключей ML-DSA-87, логин и картинка PNG. Язык `ru`/`en` и часовой пояс тоже лежат локально и на инстанс не отправляются: у `User` бекенда таких полей нет.
3. Выбор инстанса. Локальный список адресов и один активный. Адрес можно добавить вручную. При первом запуске в списке есть `https://devunit.pepeunit.com`. Схема этого инстанса открыта на `https://devunit.pepeunit.com/pepeunit/docs`.
4. Вход в выбранный инстанс. Если пользователя с этим публичным ключом ещё нет, клиент вызывает `POST /pepeunit/api/v1/users`. Дальше `POST /pepeunit/api/v1/users/auth/challenge` и `POST /pepeunit/api/v1/users/auth`. Подпись — ML-DSA-87 по байтам challenge JWT, контекст подписи пустой. Токен заголовка `x-auth-token` хранится рядом с адресом инстанса. На вебе та же чистая реализация подписи, ключ лежит в хранилище браузера.
5. Рассылка локального профиля идёт по инстансам, где вход уже есть. Логин уходит в `PATCH /pepeunit/api/v1/users/{uuid}`, картинка — в `POST /pepeunit/api/v1/icons` (`entity_type=User`). Сбой одного инстанса не отменяет остальные.

Приватный ключ хранится в защищённом хранилище платформы. Если оно недоступно, запись остаётся в файле данных приложения.

## Главное меню

Соты pointy-top, центр экрана совпадает с центральной сотой. Масштаб первого запуска зафиксирован на этом слое.

| Место | Раздел | Адрес |
| --- | --- | --- |
| центр | Аккаунт | `/people` |
| верхняя правая | Устройства | `/units` |
| верхняя левая | Пиры | `/peers` |
| средняя правая | Реестр | `/registry` |
| средняя левая | Панели | `/dashboards` |
| нижняя левая | Уведомления | `/alerts` |
| нижняя правая | Библиотека | `/library` |

Раздел «Аккаунт» — рабочий кадр аккаунта: создание ключа, логин, картинка, список инстансов, вход, рассылка. Остальные пять разделов — кадры-заглушки со стеком «назад». Поля ввода на этом шаге стоят внутри кадра, а не на гранях сот.

## Куда класть следующие экраны

- `client/lib/hive` — сота и сцена
- `client/lib/navigation` — кадры меню
- `client/lib/account` — локальный аккаунт и ключ
- `client/lib/instances` — список инстансов
- `client/lib/api` — вызовы бекенда. Сейчас рукописный клиент ручек первого запуска. Полная генерация из `client/openapi/openapi.json` подключается, когда появятся остальные экраны
- `client/lib/features` — кадры

В первый запуск не входят shadcn, мозаика фона, анимации стихий, документация внутри клиента, обновления, Grafana, топ-10 инстансов, белые и чёрные списки, кулдаун «войти во все», деревья с живыми сущностями, карточка Unit, DataPipe и смешанные размеры сот.
